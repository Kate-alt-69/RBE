RBE Build

Usage:
  ./build.ps1 [release flags]
  ./build.sh  [release flags]

Linux prerequisite preflight:
  ./build.sh --check-tools --build-linux --arch-x64

  Linux builds verify that rustup, rustc, cargo, and cc are actually usable
  before dispatching into the release/selective builders. Full release builds
  also require git and OpenSSL.

  RBE does not treat a rustup shim existing in PATH as proof that the selected
  toolchain is healthy. The preflight executes rustc/cargo and asks rustup for
  the installed target list. If a cached toolchain is incomplete/corrupt (for
  example rustup reports "missing manifest in toolchain"), RBE automatically
  removes/reinstalls the selected toolchain once before continuing.

  Environment controls:
    RBE_RUST_TOOLCHAIN=<toolchain>
                           Select the rustup toolchain used by Linux builds.
                           Default: stable
    RBE_BUILD_AUTO_REPAIR_RUST=0
                           Disable automatic repair of a broken cached Rust
                           toolchain and fail immediately instead.
    RBE_BUILD_CACHE_DIR=<path>
                           Root for RBE's reusable build cache. Cargo artifacts
                           are stored under <path>/cargo-target.
    CARGO_TARGET_DIR=<path>
                           Explicit Cargo artifact cache override. When set,
                           RBE respects this path directly.

  Shared Cargo cache precedence:
    1. CARGO_TARGET_DIR
    2. RBE_BUILD_CACHE_DIR/cargo-target
    3. XDG_CACHE_HOME/rbe-build/cargo-target
    4. <RBE>/.cache/rbe-build/cargo-target

  RBE uses one shared Cargo target directory across Container, Engine, service,
  cloud_node, backend, RPX, and SDK builds. This lets Cargo reuse unchanged
  crate artifacts across RBE's separate workspaces instead of recompiling the
  same dependencies for each sub-build. Cargo remains responsible for all
  fingerprint/target/profile/feature validity checks.

  On Render, XDG_CACHE_HOME is persisted between builds, so the shared Cargo
  target directory is restored on later deploys unless the Render build cache
  is explicitly cleared.

  Debian/Ubuntu hosts normally need:
    build-essential git openssl rustup

Selective builds:
  ./build.ps1 --only-<component> [platform/arch flags]
  ./build.sh  --only-<component> [platform/arch flags]
  ./build.ps1 --build-sdk [--only-backend|--only-rpx] [platform/arch flags]
  ./build.sh  --build-sdk [--only-backend|--only-rpx] [platform/arch flags]

Selective components:
  backend       Compile only the production backend binary
  service       Compile only the service binary
  cloud-node    Compile only cloud_node
  container     Compile only container-bin and emit it as container(.exe)
  rpx           Compile only RPX
  sdk-backend   SDK backend selector; use with --build-sdk

Selective semantics:
  --only-<component> means ONLY compile that selected component. It does not run
  the normal secure release dependency choreography first.

SDK bundle:
  --build-sdk              Build the complete project-local SDK bundle
  --build-sdk --only-backend
                           Build only the SDK backend binary
  --build-sdk --only-rpx   Build only RPX

PowerShell-friendly aliases:
  -build-sdk
  -only-backend
  -only-service
  -only-cloud-node
  -only-container
  -only-rpx
  -only-sdk-backend

Legacy compatibility aliases:
  --cloud-node-only, --build-cloud-node, -CloudNodeOnly
                           Equivalent to --only-cloud-node

Platform flags:
  --build-win, --build-win10, --build-win11, --build-windows
                           Build Windows targets
  --build-linux            Build Linux targets
  --build-macos            Build macOS targets
  --build-all              Build the default release target matrix

Architecture flags:
  --arch-x64               Target x86_64
  --arch-x86               Target i686
  --arch-arm, --arch-arm64 Target aarch64
  --arch-armv7             Target armv7

Configuration:
  --check-tools            Linux: run prerequisite/toolchain verification and exit
  --musl                   Linux: use musl targets
  --no-embed               Full release: do not embed container-bin into backend
  --dev-content            Full release: copy development api/module content
  --debug                  Build debug profile instead of release
  --target=<triple>        Build one exact Rust target triple

Examples:
  ./build.sh --check-tools --build-linux --arch-x64
  ./build.ps1 --only-backend --build-windows --arch-x64
  ./build.ps1 -only-cloud-node --build-linux --arch-arm64
  ./build.ps1 --build-sdk --only-rpx --build-linux --arch-x64
  ./build.sh --only-container --build-linux --musl --arch-x64

Without --build-sdk or --only-<component>, the normal secure release builder is
used and may build/package container, service, cloud_node, and backend together.
